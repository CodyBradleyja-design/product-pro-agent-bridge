# 【任务卡】FULOE 图片采集 → OSS → 小程序链路可执行性核查（只读）

- **任务编号：** T20261126-001
- **任务类型：** report / read-only feasibility check
- **任务目标：** 请 WorkBuddy 在本地实际环境中检查：微购相册、微信群文件图片是否能稳定采集；本机是否具备分批、断点续传、去重及上传 OSS 的执行条件；FULOE 后端和微信小程序是否具备读取 OSS 图片的接入条件。给出逐项“可执行 / 部分可执行 / 不可执行”结论及证据。
- **执行范围：** 仅检查 WorkBuddy 当前本机、已授权的图片来源应用、FULOE 现有代码目录、现有 OSS 配置状态和小程序现有配置。只读，不执行批量导出或上传。
- **输入材料：**
  1. 微购相册（用户口述总量十几万张图片）。
  2. 微信群文件及聊天图片（包括已缓存图片、群笔记图片；仅核查图片来源和文件元数据，不读取无关聊天内容）。
  3. 现有 FULOE 后端代码与微信小程序代码。
  4. 历史任务 T20261123-003 曾要求将门店电脑已收集的 82,771 张图片上传至 OSS 桶 fuloe-images /wechat-group/，但回执为 BLOCKED_REFUSED（payment 分类）。请核实当前阻塞规则及准确原因，不要重试旧任务。
- **执行要求：**
  1. **只读检查**：不得批量导出、上传、删除、覆盖、移动或改名任何图片；不得修改生产服务器、OSS Bucket 权限、DNS、域名、微信小程序配置或后端代码；不得安装软件或修改系统设置。
  2. 图片来源核查：分别检查微购相册和微信群图片的可访问方式、是否有官方批量导出功能/接口、当前可见数量、文件格式、是否存在本地缓存、是否能按批次稳定采集；说明需要人工登录/扫码/保持微信运行等条件。不得读取与图片核查无关的客户聊天正文。
  3. 采集程序核查：检查本机是否已有图片采集脚本、Python 环境、SQLite 或其他任务状态记录；是否支持分批、断点恢复、失败重试、SHA-256 去重；若没有，列出需要新增的模块和依赖，不要自行安装。
  4. OSS 核查：检查是否已配置 OSS Bucket、地域、Endpoint、目标前缀及本机上传凭据是否存在且具备必要权限。只报告“凭据存在/缺失、权限可能满足/不足”；严禁读取、显示、复制或回写 AccessKey、Secret、Token、Cookie、密码等任何凭据。不得做试上传或权限变更。
  5. 后端核查：确认当前 FULOE 后端框架、图片相关数据库表、图片登记/分页查询/授权 URL 接口是否已存在；只记录代码路径、接口路径和检查结论，不改代码。
  6. 小程序核查：确认图片组件、后端请求、downloadFile 域名配置、HTTPS 域名配置现状；区分代码中已有配置和微信公众平台后台尚未核实的配置。不得修改线上配置。
  7. 判断链路是否可以按以下结构实施：来源 → WorkBuddy 分批采集 → 本地任务台账/去重 → OSS → 后端登记及查询 → 小程序展示。逐段列出前置条件、缺口、风险、实施难度。
  8. 特别核查 agent-bridge 当前 queue 模式、自动分类规则和人工执行入口。说明此前 OSS 图片上传任务为何被识别为 payment，以及怎样按正确授权流程执行文件上传任务；不得绕过安全闸门或伪装任务类型。
  9. 如果只读检查确认可行，给出 100～300 张图片试点的具体执行步骤、所需用户确认项、回滚办法和验收标准。**本任务不执行试点上传，也不启动十几万张图片迁移。**
- **输出要求：** 将报告写入 `tasks/done/T20261126-001.md`，必须包含：
  1. 微购相册采集能力结论；
  2. 微信群图片采集能力结论；
  3. 本地采集/断点续传/去重能力结论；
  4. OSS 当前配置与权限检查结论（不含任何密钥）；
  5. FULOE 后端接口和数据库现状；
  6. 小程序图片读取与域名配置现状；
  7. agent-bridge 队列及拒绝原因；
  8. 端到端可执行性矩阵；
  9. 100～300 张试点计划、风险和验收标准；
  10. 明确区分“已验证”“待验证”“建议新增”，不允许把推测写成事实。
