# T20261118-001 找金每日同步：把 001 上已下载的找金数据接进手机版小程序

**任务目标**

用户说 001（店里 Windows 电脑）已经把找金的所有货都下载下来了，每天定时更新。Muse 这边手机版小程序已经有 30,562 款商品（11 月 17 日从 001 拉的），真图正在往自己 OSS 传（已传 5,550 款）。现在要把 001 的每日更新接进小程序，做到：找金上新我上新、找金下架我下架、价格库存跟着变，不用 Muse 每天重新去爬找金。

**背景**

- Muse 的云浏览器登不进找金网页版（滑块通过后一直卡“登录中”），只能靠 001 本机已登录的找金账号和每日下载。
- Muse 已学完找金网站大半，确认详情页按款号 pId 走、无开放接口、无“立即购买”（下单走购物车）。
- 001 目录总计约 33,932 款、在架约 31,953 款、约 171,162 张图（11 月 17 日数据）。

**执行范围**

只读核查 + 出方案。不改 001 上的任何文件、不改服务器、不改网站代码、不碰找金账号密码。

**执行要求**

1. 核查 001 上找金每日定时更新的实际情况：更新程序或脚本是什么、在哪、每天几点跑；每次更新覆盖哪些内容（新上架款、已下架款、价格、库存、图片？）；更新结果存在哪、什么文件格式；最近一次成功更新是什么时候、更新了多少款。
2. 给一个 Muse 能消费的每日增量方案：比如每天在固定位置生成一份增量清单（新增款号、下架款号、价格或库存变动款号），或把更新后的清单文件放到 Muse 能拉到的地方（桥接仓库，或 001 上 Muse 已有 SSH 直连通道的固定路径）。方案要写清楚：文件放哪、什么格式、Muse 怎么取、多久取一次。
3. 如果每日更新里还没有价格或库存变动，只管新品和下架，也如实写清楚，不要编。
4. 遇到权限或程序打不开的情况，记录实际现象就停下，不要绕过去、不要替用户输账号密码。

**输出要求**

写 tasks/done/T20261118-001.md，包含：每日更新程序的位置与运行时间、最近一次更新的时间与规模、更新内容清单（新品、下架、价格、库存、图片各有没有）、增量清单的落地方案（路径、格式、Muse 取法）、以及哪些暂时做不到。只贴小段命令输出，禁止贴密钥、配置值、密码。
