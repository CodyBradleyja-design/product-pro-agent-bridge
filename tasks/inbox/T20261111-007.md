# T20261111-007｜FULOE.COM 网站现状核查与平台升级接入方案

目标：查清 fuloe.com 的注册商、DNS托管商、网站托管商、CMS/建站系统、代码/数据库归属、后台入口及当前备份情况；在不影响线上网站的前提下，提出官网升级与 Product Pro 接入方案。

- 以上只能证明页面有 WordPress 痕迹，不能据此断定网站托管在 WordPress.com、域名注册在万网，或服务器在阿里云。

## Buddy 执行要求
1. 先只读检查本地现有工程、历史部署记录、域名配置资料、WordPress/主机配置、网站备份和相关 Git 文档；不要扫描/猜测密码，不要尝试登录未授权账户。
2. 如本机已保存合法授权的站点配置或访问令牌，只确认其存在及权限范围，不要把密钥写入报告/Git，也不要调用任何写入接口。
3. 核实并分别报告：
   - 域名注册商、到期日、域名状态（可从授权账号或权威WHOIS核验）
   - DNS托管商、NS、A/AAAA、CNAME、MX、TXT等关键记录（仅记录必要脱敏信息）
   - 网站托管/服务器供应商、站点部署位置、是否 WordPress.com 或自托管 WordPress、主题/插件概况
   - 当前后台入口、账号归属、是否有可用的官方 API/WordPress REST API/连接器
   - SSL证书、备案状态（如适用）、备份时间与恢复方法
   - 现有页面、栏目、外链（尤其首页指向 aidiaidi.com）、联系资料是否需要用户确认
4. 形成两种可行路线比较：
   A. 保留当前 WordPress 官网，先做品牌内容和页面升级；Product Pro AI平台以独立子域名（如 app.fuloe.com）接入，避免把重型应用硬塞进 WordPress。
   B. 保留 WordPress 作为品牌官网/CMS，另建独立应用前端与后端，通过安全API/SSO连接；给出成本、维护、权限和迁移风险。
5. 设计目标网站信息架构：品牌首页、品牌故事、珠宝系列/商品详情、3D/AR展示入口、AI宣传内容、供应链/商家入驻入口、AI搭子登录入口、联系与隐私/服务条款。
6. 给出 WordPress 内容管理与自定义开发的边界；不要把客户微信数据、私有群资料、原始商品图片直接放入公开网站或公共 Git。
7. 制定安全实施步骤：全站文件+数据库备份、导出 DNS 快照、测试环境、页面改版预览、回滚方案、用户验收后再发布。
8. 不要改 DNS、Nameserver、域名注册商、主机、WordPress 页面/插件/主题、数据库、生产代码；不要安装插件、购买服务、充值或发布。所有写操作必须先提交计划并等待用户明确批准。
