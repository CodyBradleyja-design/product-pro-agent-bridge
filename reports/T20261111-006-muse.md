## 一、Web 3D/AR 技术兼容性评审

### 1.1 技术路线：GLB/glTF 为主，USDZ 为 iOS 补充

| 项 | 评审意见 |
|---|---|
| 模型格式 | 首选 **GLB**（glTF 二进制单文件）：体积小、可内嵌贴图、加载快，是网页 3D 事实标准。源文件可用 glTF + 外链贴图存档，发布时转 GLB。iOS Quick Look 需另备 **USDZ**，两者由同一源模型导出，不维护两套模型。 |
| 网页查看器 | 首选 **`<model-viewer>`**（Google 开源 Web Component）：一行标签实现旋转/缩放/自动旋转/AR 按钮，iOS 自动走 USDZ Quick Look、安卓自动走 Scene Viewer，不支持时可配回退图。备选 three.js（定制自由度高，但开发与维护成本高，首版不建议）。 |
| iOS AR | **USDZ + Quick Look**：iOS Safari 原生支持，点击 AR 按钮即可在实景中放置查看，无需安装 App。限制：Quick Look 不支持网页内嵌交互逻辑，模型须自带尺寸（`verified_dimensions_mm` 必须真实测量填入，不得估算）。 |
| 安卓 AR | **Scene Viewer**（Google）：Chrome 安卓调起系统级 AR 查看，支持 GLB；或 **WebXR**（Chrome 安卓支持 `immersive-ar`）。限制：不同品牌机型支持度不一，须以 Scene Viewer 为主、WebXR 为辅。 |
| WebXR | 仅 Chrome 安卓等部分浏览器支持；**iOS Safari 不支持 WebXR**，不得把 WebXR 作为唯一 AR 路径。首版 AR 以 Quick Look + Scene Viewer 两条系统路径为准，WebXR 列为后续增强。 |
| 桌面端 | `<model-viewer>` 旋转/缩放即可；桌面无 AR 需求，不做摄像头试戴。 |
| 加载性能 | 单模型 GLB 建议 ≤5 MB（移动端首屏可接受上限约 10 MB）；超限则用 Draco 压缩 + 贴图降分辨率；首屏先出多角度图片占位，模型懒加载。 |

### 1.2 扫码展示页结构（建议）

```
扫码（qr_url）→ 手机商品展示页（viewer_url）
  ├─ 模型区：<model-viewer>（GLB 旋转 / AR 按钮；不支持时自动回退多角度图片）
  ├─ 商品区：标准款式名、规格（尺寸/圈口/克重范围）、商家报价、最后更新时间
  ├─ 货源入口：关联 listing（哪家店有这款）与商家权限
  └─ 证据区：模型来源、license、verified_dimensions_mm、scale_verified、version
```

要求：展示页只读公开信息；未授权供应链数据、商家内部价、客户信息不得出现在展示页。

### 1.3 模型元数据评审（任务卡 Buddy 第 2 项字段）

`model_asset_url / format / version / source / license / verified_dimensions_mm / scale_verified / viewer_url / qr_url / fallback_images` 十个字段齐全，补充三点：

1. 不同尺寸结构使用独立版本——须落成约束：`version` 与 `variant_id` 绑定，同一 style 下不同 variant 不得共用同一模型版本；相似款不得误认同款（与 005 铁律一致）。
2. `scale_verified` 为布尔值时须另有 `scale_verified_by`（测量人/方式）与 `scale_verified_at`（测量时间）；未验证的模型不得进 AR，只能当普通 3D 旋转展示，且页面须标注「尺寸未验证」。
3. `fallback_images` 至少 3 张多角度实拍（正/侧/细节），无模型时展示页直接用它，不得用单图伪造精确尺寸、重量或工艺。

## 二、三种建模路线比较

| 维度 | A. 厂家模型 | B. 多角度实拍建模 | C. AI 辅助建模 + 人工校验 |
|---|---|---|---|
| 做法 | 厂家提供现成 3D 文件（GLB/USDZ/STL 等），转格式后上架 | 多角度实拍照片 → 摄影测量/NeRF 重建 → 人工修模 | AI 由图片生成 3D 粗模 → 人工按实物校准尺寸、结构、工艺 |
| 成本 | 最低（无制作费，只有格式转换与审核人力） | 中（拍摄 + 重建算力 + 修模人力；单款约数小时） | 中低（AI 生成快，但人工校验不可省；校验成本与 B 相近） |
| 准确度 | 最高（厂家原始数据，尺寸/结构可信；须核对版本与实物是否一致） | 中高（依赖拍摄质量；黄金高反光表面是摄影测量难点，易丢细节、易变形，须偏振/柔光拍摄 + 人工修补） | 最低（AI 会「脑补」结构与纹样；尺寸、克重、工艺细节不可信，必须逐项人工校验，校验不通过即废弃） |
| 加载性能 | 最好（厂家模型通常已优化；须再压到 ≤5 MB） | 中（重建模型面数高，须减面 + 压缩） | 中（AI 模型常带冗余面，须减面 + 压缩） |
| 版权 | 须厂家书面授权（见 §四） | 自拍自有，最干净 | AI 生成部分版权归属看平台条款；须标注 AI 辅助 + 人工校验 |
| 适用 | 首选：凡厂家能给模型的款一律走 A | 厂家无模型、但有实物可拍的款 | 无模型、无实物拍摄条件时的备选；只做示意，不得当精确商品图 |
| 风险 | 厂家模型版本与在售实物不一致 | 反光导致重建失真；修模改动结构 | AI 伪造尺寸/重量/工艺，误导消费者 |

结论：**A > B > C**。首版 2–3 款演示优先选厂家能给模型的款；没有可靠模型时明确标记「示例」，诚实回退多角度图片，不得用 C 路线硬凑精确展示。

## 三、虚拟试戴后续方案（与 AR 空间展示分开）

- **分开立项**：AR 空间展示（把模型放在桌面/手掌上看）与摄像头虚拟试戴（把戒指/项链戴在真人手上/脖子上看）是两件事，不得混在同一验收里。006 只做前者。
- 试戴前置条件：① 手寸/脖围等人体尺寸标定流程（戒指需圈口标定，否则试戴无意义）；② 摄像头画面只在本地处理，不上传、不存照；③ 试戴是示意效果，须标注「试戴为模拟效果，实际佩戴以实物为准」。
- 试戴不进入首版：等 3D 展示页跑通、有真实模型、尺寸验证流程落地后再评估；试戴涉及人脸/手部图像隐私，须单独过隐私评估。

## 四、模型版权、数据隐私与多商家复用机制评估

### 4.1 版权

- 厂家模型：须取得书面授权（授权范围：展示、AR、转格式、缩略图；授权期限；是否可转授权给入驻商家）。无授权的模型不得上架；授权到期即下架。
- 他人模型/图片：不得下载、改制他人 3D 模型或商品图当自有模型；参考构图与拍法可以，搬运资产不行。
- AI 辅助建模：生成物版权按所用平台条款确定；须在 `source` 字段注明「AI 辅助 + 人工校验」及所用工具，不得冒充厂家原模。
- 模型文件本身受版权保护：`license` 字段须填授权类型（如厂家授权/自有/平台条款），不得留空上架。

### 4.2 数据隐私

- 模型元数据不含任何客户信息；展示页不收集、不上传用户摄像头画面与位置以外的信息。
- 商家信息只展示可公开字段（店名、可公开地址、联系方式）；营业执照号、内部价、进货价永不进展示页。
- 扫码访问统计只记汇总（访问量、机型分布），不记个人身份与精确位置。

### 4.3 多商家复用机制

- 模型归属分三层：平台标准模型（厂家授权给平台，所有入驻商家可用）/ 商家自有模型（仅该商家 listing 可用）/ 共享模型（厂家授权多商家，须登记授权商家清单）。
- 复用规则：同一 style 的模型可被多家 listing 引用，但每家 listing 的 `variant_id` 与模型 `version` 须对应；商家实际克重/报价仍以自家 listing 为准，模型不携带价格。
- 版本管理：模型更新即升 `version`，旧版本保留可回溯；已发布展示页的模型版本变更须经审核，不得静默替换。
- 授权过期处理：授权到期或撤销时，引用该模型的所有展示页自动回退多角度图片，并通知相关商家。
