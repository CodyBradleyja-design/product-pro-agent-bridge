## 四层实体模型评审

| 层 | 评审意见 |
|---|---|
| Style 标准款式 | 平台唯一款式 ID、类别、结构/工艺/材质特征、授权标准图、向量索引、版本。成立。须加：相似款人工确认、版本变更记录、标准图授权来源。 |
| Variant 规格 | 尺寸、圈口、克重范围、工艺、材质、品牌授权。同形状不同规格不混并。成立。须加：规格唯一性规则（款式 + 规格维度），报价只挂规格层。 |
| Store 商家 | 店铺 ID、店名、可公开地址、坐标、联系方式、认证状态、营业资质、地理数据来源与授权。成立。须加认领状态机：未认领 → 待验证 → 已验证 → 已下架/已撤销；POI 发现数据与商家主动提交数据必须分字段存放。 |
| Listing 商家上架 | store_id + style_id + variant_id，商家实物图、实际克重、可售状态、报价、更新时间、来源与证据。成立。须加：报价/库存快照过期策略（v2 提出三天未更新仅提示，须落成“提示信息可能过期”的展示规则与时间戳）；库存/价格不可从地图 POI 推断。 |
| Source / Offer | 厂家群图片、供应商报价及时间、原始证据、授权范围，关联标准款和店铺时保留置信度与人工纠错。成立。须加：证据保留期限与脱敏规则。 |

关键约束：一个标准款可对应多家供应商，一个供应商可登记多款；商家认领、商品发布必须经过验证 / 授权；报价与库存须标明最后更新时间。

## 地图 / 商家数据策略评审

- 先盘点、再决策：Buddy 只读盘点数据来源、协议、调用方式、存储与展示权、缓存期限、商业使用限制、是否允许再分发、数据质量及去重情况；现有坐标数据先备份并保留来源与采集时间。
- 百度 / 高德许可核查清单：商业使用、缓存、存储、展示、配额、再分发六项，逐项核对合同条款；不得绕过付费限制或配额。
- 百度约 5 万元报价：仅为用户口述，未核实对应哪项服务、是否含税、有效期与使用范围；不据此付款、不据此删改现有数据。
- 替代路线（按优先序）：有授权的 POI 服务 → 商家自主入驻自建库 → 公开许可数据；任何路线都不得未经许可抓取或绕过付费限制。
- 供应链地图定位：地图是商家发现与入口，不只是展示；不得把地图采集到的商家信息误当作商家已入驻或已同意展示商品。

8 步工作流（选产品 → 趋势研究 → 创意/文案 → 使用授权商品图制作素材 → 人工审核 → 一小二等平台发布 → 数据反馈）成立，补充意见：

2. 素材合规：外部平台内容仅用于趋势研究和创意参考；不默认下载、复制或改造他人受版权保护的图片 / 视频作为自有素材；保存来源 URL、作者 / 平台、抓取时间、授权 / 使用状态。
3. 商品真实性：AI 处理真实黄金商品时必须保留款式结构、比例、重量和工艺事实，不得生成误导性商品图；图片 / 视频趋势研究不等于获得复制或二次发布授权。
4. 费用管控：对 API 费用建立调用日志、单次成本、月预算和额度告警；未确认前不自动充值、不批量生图 / 视频。

## Supabase vs 本地 / 自建评审

| 方案 | 适用阶段 | 优点 | 风险 / 成本 |
|---|---|---|---|
| 本地优先 | 现在 | 原图与微信数据不出本地；零云费；符合总纲 | 多设备访问弱；备份责任在本地 |
| Supabase（Postgres + Auth + Storage + pgvector） | 阶段二候选 | 租户隔离、鉴权、向量检索一次到位 | 月费随存储/带宽涨；须先做成本预算与删除/审计方案 |
| 自建后端 | 商业化后期 | 完全可控 | 运维成本最高；不建议早期投入 |
| 对象存储 + CDN | 阶段二 | 授权缩略图分发 | 只放授权缩略图；原图不进云 |

结论：本地代理负责微信 / 本地图片，原图本地优先；云端负责商家身份、店铺目录、标准款式 ID、授权缩略图、查询索引、同步日志。多租户隔离、权限、审核、删除和数据可携带性为商业化前提，缺一不可。
